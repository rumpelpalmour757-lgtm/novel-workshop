# 小说写作工坊 r5.56

版本号 `2026-11-14-r5.56`。在上一版 r5.55（版本号 `2026-11-14-r5.55`，文件 `novel-workshop-commercial-r5.55.zip`）上做的新版本，只做维护者 2026-11-14 定下的两件事：作者改法累计放回技能目录、跟着技能包走，`install.py --upgrade` 升级时把它带进新版；写明默认的教师设置（gemini-4-argon，思考等级高）。

## 下载哪一个

- **`novel-workshop-commercial-r5.56.zip`**：完整包，给能导入技能的工具用（Claude Code、Codex 一类）。解压后先运行 `python install.py --dry-run` 预览，再运行 `python install.py` 安装；已经装过旧版的，看下面“升级要注意的”。要 Python 3.9 或更新。3,520,499 字节，SHA-256 `7726f3cef2ee3243458bfa092e2872e496adc4c5a5af4f27785231d6cfef68fb`。解压出 603 个文件，包里的 `PACKAGE-MANIFEST.json` 登记了其余 602 个的 SHA-256。
- **`portable-novel-workshop.md`**：便携单文件，给只能聊天、能传附件的 AI 用。没有可运行的脚本，也不带两个风格包。1,258,014 字节（约 56 万字符），SHA-256 `af8a265940e2f89641ce67957416cf31e38a97ba8b64f44bddc7eed338f06c6f`。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，和仓库根目录的同名文件相同。完整包里也带着 `LICENSE` 和一份按包内路径写的 `THIRD-PARTY-NOTICES.md`。

装法、用法和第一条请求见[仓库首页](https://github.com/rumpelpalmour757-lgtm/novel-workshop)和[详细用法](https://github.com/rumpelpalmour757-lgtm/novel-workshop/blob/main/docs/usage.md)。

## 改了什么

- **作者改法累计放回技能目录**：记录放在技能目录的 `novel-workshop/assets/project-packs/_author/`，一共两份：`correction-register.md` 是有效规则摘要，`correction-history.md` 放详细证据和变更历史。它跟着技能包走，不在作者档案、作品目录里另存一份。完整包不带这两份，你开了累计以后工坊才在你自己装着的技能目录里建；已经有的照用，不重建、不清空，换包也不会拿空白文件盖掉你记下的。开了以后，你新说的跨作品默认（新章全流程开没开、两项策略、交教师的默认设置）也记在 `correction-register.md`。r5.55 把它挪到技能目录以外、你的作者档案那里，这一版作废那个做法；照 r5.55 放在外面的，工坊先问你一句，你同意了才照原样挪回，原处只留一句挪去了哪里，不留两份。
- **升级带上你的记录**（`install.py`）：`--upgrade` 先把装着的 `novel-workshop/assets/project-packs/`（`_author/` 和你放进去的作品资料）复制进新版，每个文件核一次 SHA-256，再换上新版；预览里列在 `carried` 下。新包在那里也带了同名而内容不同的文件的（一边是文件、另一边同名的是文件夹，或者名字只差大小写的，也算），安装器在写任何东西以前停下，退出码 1，列出这些文件，要你用 `--keep installed` 或 `--keep package` 选一边；`--dry-run` 也列出（`conflicts`），退出码也是 1。“已经是这一版”只看 `assets/project-packs/` 以外的文件，那里多了你的记录仍算同一版。升级途中装着的技能目录或要带的文件变了，就停下，什么也不换。目录联接（junction）和符号链接一样拒绝。`--help` 写了退回旧版时记录在哪。
- **导出**（`scripts/export_portable.py`）：个人导出默认仍不带 `assets/project-packs/`，命令行说有几份没带、其中几份是 `_author/` 里的；加 `--include-projects` 带上整个 `assets/project-packs/`，包括 `_author/`，只有 `_author/` 的也能用。出错时打印 “Export stopped: …”、退出码 1，不再出 traceback。`--mode sale` 照旧一律不带；便携单文件不展开这个文件夹，带和不带时逐字节相同。
- **默认的教师设置**：章节门开着、初稿由你交教师的，工坊交初稿时说清默认的教师设置：交给 gemini-4-argon，思考等级选“高”（High）。这只是默认，可以改：作者档案或作品档案另写了别的教师的，照写的；你这一次另说的，照这一次。不说明用它写得更好，也不说明审得更好。登记回传时，教师一栏（`teacher_name`）照实际填：你说了交给谁就写谁；说“照默认交的”，写交初稿时说的那个默认；你没说、作者档案或作品档案里定了默认教师的，写那个默认，并写明是照默认填的；档案里也没定的，工坊问你一句；你也说不清的，写未知。已经登记过的回传不追改。
- **写作台**：代码没有改，只补了说明：Gemini 侧栏的请求不指定思考等级，用模型自己的默认，工坊没有核对过那是不是“高”；Google AI 侧栏照默认设置的，模型选 gemini-4-argon、思考强度选 High，这条路只用模拟程序测过；两个侧栏一次最多发 6000 字，整章初稿发不全的，在你自己用的 Gemini 界面里选“高”交。
- **数目**：完整包 600 个文件变 603 个，多的是三个测试文件；方法参考仍是 48 篇。
- **没有动的**：交付门绑定的五个检查脚本（`workflow_guard.py`、`punctuation_lint.py`、`prose_lint.py`、`fact_guard.py`、`project_state.py`），章节门、学习循环、示范记忆、对白检查的脚本，写作台的代码，工坊宪法、交付门卡、改稿卡和 83 张风格卡的卡库，都和 r5.55 逐字节相同。

- 升级和退回：用 r5.55 的发布包和这一版的包，在临时目录里实际走过两遍。维护用的升级退回演练 11 步全过；带记录的演练 20 步全过：在装好的 r5.55 里放两份新写的中性记录，升级以后两份在新版里、和放进去的逐字节相同，同一版再装是 `unchanged`；用 r5.55 的安装器退回以后，两份在说明页写的那个备份位置；说明页的两种取回办法也各走了一遍。“工坊先问你一句再挪回”是手动模拟的。

## 升级要注意的

- 已经装过旧版的，用 `python install.py --upgrade`（装的时候带了 `--dest` 的也带同一个；先加 `--dry-run` 看输出，技能后面写 `upgrade` 或 `unchanged` 才对）。不加 `--upgrade` 时，装着的版本和这一版不同，安装器就停下，什么也不装。
- **从 r5.55 升上来**：先 `python install.py --upgrade --dry-run` 看一遍，再 `python install.py --upgrade`。装着的 `assets/project-packs/` 里有什么（作品资料，或者你自己放进去的 `_author/`），都列在 `carried` 里带进新版；完整包不带那里的任何文件，所以不会有 `conflicts`。照 r5.55 的说明放到作者档案那里的改法累计，安装器不碰；升级以后工坊看到了，先问你一句，你同意了才挪回技能目录。从 r5.54-merged 升到 r5.55 时被移进备份、一直没取回的，在装技能的目录下（默认 `~/.codex/skills`，Claude Code 是 `~/.claude/skills`）的 `.novel-workshop-backups/<时间>/novel-workshop/assets/project-packs/_author/`。交付记录照旧。
- **从 r5.54-merged 或更早升上来**：命令一样，装着的 `assets/project-packs/`（r5.54-merged 默认把改法累计放在 `_author/` 里）带进新版。中间 r5.55 那一版的不兼容变化（章节门、学习循环、示范记忆、对白检查）照样适用，见 [r5.55 的说明](https://github.com/rumpelpalmour757-lgtm/novel-workshop/releases/tag/r5.55)。从 r5.54-merged 升上来的，交付记录照旧；从 r5.54、r5.53 的包（文件名不带 merged）升上来的，以前记的整章交付记录读成过期（STALE），要用这一版重跑一次检查。
- **对不上时怎么选**：新包自己在 `assets/project-packs/` 下带了文件、又和装着的对不上的（比如带着自己 `_author/` 的自用包），安装器停下，不做备份，什么都不换。明确选一边再运行：`python install.py --upgrade --keep installed` 留装着的那一份，带进新版，新包里的同名文件不装；`python install.py --upgrade --keep package` 装新包里的那一份，装着的那一份只留在备份里。一次对所有对不上的文件选同一边，不能逐个文件选；两边都记了新内容的，选哪一边都会丢另一边，要手动合并，被丢的那份在新包里或备份里。
- **整包上传、不用 `install.py` 的**：换新包以前，把旧包里的 `skills/novel-workshop/assets/project-packs/` 整个复制到新包同一位置；有 Python 的，也可以用新包的 `install.py --upgrade --dest` 指到放着旧 `novel-workshop` 文件夹的那个文件夹，做法见包内 `QUICKSTART.md`。
- **退回 r5.55 时记录在哪**：用 r5.55 的包运行 `python install.py --upgrade`。r5.55 的安装器不带 `assets/project-packs/`，退回以后技能目录里没有这个文件夹；记录在这次退回新生成的备份里：`<安装位置>/.novel-workshop-backups/<时间>/novel-workshop/assets/project-packs/`，取最新的那个时间文件夹。r5.55 从作者档案读改法累计，要在 r5.55 里接着用，照 r5.55 的说明页（`references/author-preferences.md`“作者改法累计”）把 `_author/` 里的两份放到作者档案那里；以后再升回 r5.56，工坊看到了会先问你一句再挪回技能目录。
- **退回 r5.54-merged 或更早**：同样用旧包的 `python install.py --upgrade`（更早的包怎么退，见[回到旧版](https://github.com/rumpelpalmour757-lgtm/novel-workshop/blob/main/docs/versions.md#回到旧版)），再把备份里的 `project-packs` 文件夹复制回 `<安装位置>/novel-workshop/assets/`。复制回去以后，旧包的 `install.py` 不加 `--upgrade` 再运行会报 “Existing skill differs”（r5.55 的是这样，更早的没有逐个试过）；不要照它的提示加 `--upgrade` 再装同一个旧包，那样会把整个目录连同记录再移进备份。这一版的章节门、学习循环脚本和 r5.55 相同；r5.55 写下的章节记录和学习记录，r5.54-merged 的脚本能不能读，没有验证，退回以前先另存一份。
- 手动回退（把备份里的目录移回原处）的：备份里的 `assets/project-packs/` 是升级那一刻的；移走现装的目录以前，先把它的 `assets/project-packs/` 另存一份。
- 以后从更新的版本退回 r5.56：用 r5.56 的包运行 `python install.py --upgrade`，记录照样带进 r5.56，较新的一版整份留在备份里。
