## 包里有什么

日常写作只用 `novel-workshop`，其余部分不用管。

| 部分 | 在包里的位置 | 负责什么 | 什么时候用 |
| --- | --- | --- | --- |
| `novel-workshop` 写作核心 | `skills/novel-workshop/` | 创作、改稿、审稿、连续性、项目接续、风格卡；48 篇方法参考、作品模板、检查脚本和本地工作台；另带四个默认不开的模块（章节门、学习循环、示范记忆、对白声纹检查，见[四个可选模块](modules.md)），和一页默认关着的“从改稿记录里学编辑判断” | 日常写小说 |
| `darwin-novel-workshop` 维护技能 | `skills/darwin-novel-workshop/` | 诊断工坊方法、比较新旧规则、准备与验证改进候选 | 你明确要求评估或改进工坊时；普通写作不会启动它 |
| 两个风格包 | `skills/novel-workshop/assets/style-packs/` | 都市高武风格引擎库 v2.0.2、小说实感与去 AI 味引擎 v17.1.2（r5.47 起随完整包） | 默认不启用，见下文[风格包](#风格包) |
| TypeSafe 可选开发扩展 | `optional/typesafe-ai/` | 辅助开发结构化提取、分类、排序和规则判断功能，不生成小说 | 开发辅助工具时；默认不安装 |

便携单文件 `portable-novel-workshop.md` 只有写作核心：48 篇方法参考、作品模板、交付门卡、改稿卡、工坊宪法和当前的风格卡库都展开在里面。四个可选模块和“从改稿记录里学编辑判断”的说明，以及三个模板（示范案例模板、对白检查的空配置、编辑判断模板）也在里面，但没有脚本。它不带风格包，也不执行脚本。

## 按环境导入

| 环境 | 做法 | 能用到什么 |
| --- | --- | --- |
| 能导入技能的工具（如 Claude Code、Codex 一类） | 导入 `skills/novel-workshop` 和 `skills/darwin-novel-workshop` 两个完整目录，或运行 `install.py` | 完整方法；模型有执行权限时，还能运行检查脚本 |
| 有项目指令和附件的聊天产品（如 Claude 项目、ChatGPT 项目或自定义 GPT） | 交付门卡全文贴进项目指令；常改稿、去 AI 味的，连同改稿卡一起贴；上传单文件作为参考文件 | 方法都在单文件里，但模型多半只检索片段；脚本一般不会运行，改稿照改稿卡人工对照 |
| 只有对话框、没有项目指令（但能传附件） | 第一条消息里贴交付门卡全文（改稿时连同改稿卡），再上传单文件 | 同上；新对话要重新提供 |

两张卡的全文见[聊天用的两张卡](chat-cards.md)，单文件里也有。

### 能导入技能的工具

1. 解压完整包，找到 `skills/novel-workshop/` 和 `skills/darwin-novel-workshop/`。
2. 按平台的导入方式分别导入两个完整目录，保留里面的文件和层级。平台没有导入功能，就改用单文件。
3. 在新对话中发送：

```text
请使用小说写作工坊。先确认你能读取它的说明，
再根据我随后提供的题材、设定和稿件开展工作。
```

平台确认读得到以后再发任务。不要只凭“上传成功”判断技能已经被读取。

**用安装脚本**（需要 Python 3.9 或更新版本）。在解压后的目录打开终端，先预览，再安装：

```text
python install.py --dry-run
python install.py
# macOS、Linux 上找不到 python 时，把 python 换成 python3
```

默认装到 Codex 的 `~/.codex/skills`。用别的工具的，用 `--dest` 指向那个工具的技能目录。比如 Claude Code 的个人技能目录是 `~/.claude/skills`：

```text
python install.py --dest "~/.claude/skills" --dry-run
python install.py --dest "~/.claude/skills"
```

别的工具的技能目录，查它自己的说明，再把上面的路径换掉。

安装器遇到同名而内容不同的技能会停下，不覆盖；内容相同的跳过。只有要开发辅助功能时，才加 `--include-dev`，它额外安装 TypeSafe。安装只是把文件放进技能目录，不会启动工作台、联网服务或定时写作。

### 升级与回退

```text
python install.py --upgrade --dry-run
python install.py --upgrade
```

装的时候带了 `--dest` 的，升级也带同一个 `--dest`。`install.py` 不记上次装在哪，不带就按默认的 `~/.codex/skills` 来。例如装在 Claude Code 个人技能目录里的：

```text
python install.py --dest "~/.claude/skills" --upgrade --dry-run
python install.py --dest "~/.claude/skills" --upgrade
```

先看 `--dry-run` 的输出：`destination` 应当是你实际在用的那个技能目录；`skills` 里每个技能的 `action` 应当是 `upgrade`，内容和新包一样的写 `unchanged`。写 `install` 说明这个目录里原来没有装过它，多半是目录指错了：照这样装下去不会报错，只是在那个目录里新装一份，你实际在用的那一份没有换。

旧版先整份移到目标目录下的 `.novel-workshop-backups/<时间>/`，校验通过后才装新版；中途出错会把旧版放回原处。回到旧版的办法见包内 `QUICKSTART.md`，也可以看[版本、下载与来源](versions.md#回到旧版)。个人改过的技能文件，升级前另存一份；作品正文和状态文件放在作品目录，不放在技能目录。

**升级以后的旧交付记录。** 从合并候选版升到 r5.55，交付记录照旧：交付门绑定的五个检查脚本两边逐字节相同（这是按脚本哈希推的，没有在 r5.55 上另跑）。从 r5.53、r5.54 的完整包升上来，以前用交付门脚本（`workflow_guard.py`）记下的整章交付记录，在新版里会显示 STALE。原因是交付记录绑定着检查脚本的版本，而从合并候选版起，文字检查脚本 `prose_lint.py` 和那两版不一样。这不说明稿子出了问题，把检查重跑一次就行：`reserve` 一轮，再 `record`（占一轮复查额度）。原样重交旧审稿，只是把旧结论绑到新脚本上，不等于按新方法重读过；交付说明里写清是哪一种。反过来，拿 r5.55 或合并候选版记下的交付记录回那两版去读，也是 STALE。只在聊天里用、没跑过交付门脚本的，没有这回事。

**从合并候选版升上来，章节门的默认变了。** 新开的章，写前看图和初稿由你交教师两项默认开着（合并候选版默认关着）；合并候选版下已经开始、当时没记策略的章照旧按两项都关走，`chapter_gate.py status` 里显示 `earlier_version`，工坊见到会问你一句。已确认的阶段在记录里缺你的原话或出处的，读成未确认。详见[四个可选模块](modules.md#章节门)。

**作者改法累计。** 它放在你的作者档案里，不在技能目录，`--upgrade` 不动它。早先版本把它放在技能目录的 `assets/project-packs/_author/` 下的，升级以前先移到作者档案那里；已经升级过的，到安装位置下 `.novel-workshop-backups/<时间>/novel-workshop/assets/project-packs/_author/` 里取回。

**平台自己管的技能目录。** 有的平台把导入的技能放在它分配的目录里（目录名是一串编号），`install.py` 更新不到那一份。这类平台用它自己的更新或重新导入；怎样核对装上的是哪一版，见包内 `USAGE.md` 第一节“平台自己管的技能目录”。

用单文件的，换上新的单文件，新开对话重新上传即可。

### 有项目指令和附件的聊天产品

1. 把[交付门卡](chat-cards.md#交付门卡)全文贴进项目指令。常改稿、去 AI 味的，连同[改稿卡](chat-cards.md#改稿卡)一起贴（r5.48 起）。
2. 上传 `portable-novel-workshop.md` 作为参考文件。
3. 发任务，附上本轮要用的稿子和设定。较长的作品可以先给当前章节、前情摘要和人物资料。

为什么要另贴卡：单文件约 56 万字符（约 29.9 万个汉字），很可能超过模型一次能读的长度，平台多半只按需检索附件里的片段，不会通读；交付门卡只有一页，放在指令里，那几条底线就一直在上下文中。聊天产品这条路只做过模拟检索的测试，没有在 ChatGPT、Gemini、Claude 网页版里实测过附件能读到多少（见包内 `VERIFICATION.md`）。这类环境一般不会运行脚本，这时 AI 应当把程序检查写成 UNTESTED，不能写成 GREEN。

### 只有对话框

指没有项目指令、但能传附件的环境。第一条消息贴交付门卡全文（改稿时连同改稿卡），再上传单文件，然后发任务。新开对话要重新提供。

### 换会话

把当前稿、相关前文、已确认状态、未决问题和下一步带过去。接续摘要和原文各有用途，最好一起保留。交付文件不代表平台有自动记忆或长期保存能力；原稿、设定和满意的版本请自己保存，换平台时让 AI 先核对当前版本。

### 确认它真的读了

- 开工前问一句：“这次按哪一级处理？会读哪些模块和小节？”回答应当和工坊的分级表对得上。
- 抽查：请它逐字引用其中一个模块里的一条规则（例如中文标点模块对【能力名】的写法）。引不出来或引错，说明没读到；让它先读，再开工。
- 交付后请它列出这次读过的模块（默认不附在正文后）。清单里没有的模块，不能当作已经按它检查过。

这些办法只能发现“没读”，不能证明“读懂了”。

## 请求怎么写

只需让 AI 知道：这次做什么，依据哪一版，哪些地方必须保留，以及你希望收到什么。用日常的话说，不用记固定命令。

### 通用模板

```text
请使用 novel-workshop 小说写作工坊。

本轮任务：【写新章／续写／精修／审稿／检查连贯性／整理旧稿】
依据材料：【原稿、前文、设定、图片或已采纳版本】
必须保留：【情节顺序、人物认知、指定句子、结尾、视角等】
允许调整：【句法、标点、重复、场景组织、对白等】
输出要求：【只要正文／正文加说明／先列问题／分别保存章节】

请按任务范围读取需要的模块；
未执行的检查照实说明，未读到的前文不要补成事实。
```

### 常用请求

| 任务 | 可以这样说 |
| --- | --- |
| 开篇 | 请用工坊构思小城悬疑开篇，主角是修钟师；先给两个方向，我选后再写正文。 |
| 续写 | 先读第七章定本和本章大纲，续写第八章，保持持物、伤势和知情范围，不提前揭露幕后人。 |
| 整章精修 | 按 L1 精修这一章，只改句法、标点、重复和对白衔接；保留情节、认知、态度、动作先后和结尾。 |
| 只审不改 | 每条问题给原文位置、依据、影响和最小修改建议，暂时不改正文。 |
| 去模板腔（就是去 AI 味） | 查重复解释、总结旁白、机械短句和无作用小动作；保留有用的心理变化，不统一改成碎句。 |
| 回查后文 | 第八章改了物品去向，请找第九至十二章依赖它的位置，先列问题，不覆盖后文。 |
| 多线并行 | 主角线和对手线交替推进，列清每次切换的阅读收益，以及消息怎样跨线传递。 |
| 旧稿导入 | 保留原稿，整理人物、时间线、已发生事实、未采纳方案和当前停点；冲突并列，不续写。 |
| 图片起步 | 我喜欢这张图的拥挤和破旧，先给两三段短候选，每段说明借了什么。 |
| 图片局部 | 只借布局和灯光，不借服装与人物身份；灯光只用于这一场。 |
| 用风格卡 | 这一场先对照风格卡，每层只挑最合适的一张，对不上就不用；先说卡名和理由再写，人物口吻照我的原文。 |
| 点名风格卡 | 这一场用 hemingway-iceberg 加 tense-suspense-probe，只借方向，人物口吻照我前几章。 |
| 不用风格卡 | 这一场不加载风格卡，照我前几章的写法。 |
| 换会话 | 整理当前版本、最新正文、已确认状态、未决问题和下一步；摘要和原文一起保留。 |
| 评估工坊（维护用） | 使用 Darwin 维护技能，评估润色为什么改变人物语气；先只诊断，不改已安装技能。 |
| 每章逐步确认（先开启） | 以后每写新的一章都走完整流程，一步一步给我看，我确认了再往下。 |
| 教师改稿带回来 | 教师的改稿回来了，改的是第八章这一版初稿。先别动我的稿子：并排列出原句和教师的改句，每一处讲明多了什么、丢了什么，你建议采纳、拒绝还是暂缓；整份方案我确认了再改。 |
| 改完复查 | 改完按新稿再查一遍，不拿上一版的结论顶；采不采纳我看了再说。 |
| 记住改法（先开启） | 这一处改法我认，记成这本书的示范，标明是我认可的；下次类似的改稿先参考，最多三条。 |
| 对白声纹扫描 | 用对白声纹检查扫一遍这一章，只扫不改；命中的句子列给我回读。 |

风格卡的三段完整提示词（自动挑卡、手动指定、不用卡）见[风格卡](style-cards.md#直接复制使用)。表里最后五行对应[四个可选模块](modules.md)，是本页新写的说法；包内 `EXAMPLES.md` 有 29 条示例，第 29 条是新章七阶段和教师回传，学习循环、示范记忆和对白检查还没有例子。

### 整章精修请求

```text
请使用小说写作工坊，按 L1 精修这一章。
只调整句法、标点、重复表达、台词衔接和无作用的小动作。
保留情节顺序、人物认知、人物态度、动作先后、关键细节和结尾。

按修改的五道工序检查。改后对照原稿，
列出原稿有而修订稿消失的重要细节，留不留由我决定。
不要为了增强体验新增伤势、疼痛或世界观设定。

交修改稿，正文之外简要说明实际检查范围。朗读由我自己做。
```

## 写小说常卡在哪里

下面按写小说时最常卡住的七处来说：每一处写工坊怎么做、方法在包里哪一篇、你可以怎么开口。路径的找法见本页开头；请求里的人物和情节只是占位，换成你自己的。

照实说：这里写的是让 AI 照着做的方法，不是效果保证。工坊只和不用工坊的 AI 比过一次（r5.46，规模小，执行和评审都是同一类模型）：改 AI 腔重的稿子，排第一的都是不用工坊的；从头起草，工坊多数在前。之后没有再比过。对白是不是更像人、更有感情，没有验证；好不好由你读了定。

### 开篇：有个念头，不知道从哪写起

先把点子变成人物想要什么、挡在前面的是什么、会发生哪些具体的事，默认展开一个有取舍的方案；想比较，就说“先给两三个方向”，它再列不同路线，你挑了再写正文。只有一张喜欢的图加一句感受也能开始：它照图里看得见的东西写两三段短候选，每段说明借了图里的什么，再问你喜欢哪段。你没给过自己写的文字时，它会照实说这次没有你的声音样本，不冒充你的口吻。

在哪里：`references/planning.md`；`references/drafting.md`“从一张图和一句感受开始”。

```text
请用小说写作工坊构思一个小城悬疑的开篇，主角是修钟师。
先给两个开场方向，我选了再写正文。
```

### 续写：隔了几天，接不上上一章

先取上一章结束时的地点、时间、人物、动作、目标和没兑现的承诺，从接下来的动作接着写。动笔前，它在内部整理一张本章工作卡，只带“不知道就会写错”的信息。没读到的前文不补成事实，还没到揭晓的答案不提前说破。

在哪里：`references/drafting.md`“起点与节奏”“本章工作卡”；长篇连载另见 `references/serial-production.md`。

```text
先读第七章定本和本章大纲，续写第八章。
保持持物、伤势和知情范围，不提前揭露幕后人。
```

### 改稿：改了几遍，还是一股 AI 味

先定改到什么程度：只动字句、一个事实都不加；在已有事实里改写；还是重写这一场。再逐句找替读者下结论的情绪词、现成的身体反应、“不是……而是……”式的道理、点题式收尾这类句子，从人物正在做的事、注意到的东西里改，不是换个说法留下。改完对着原稿两头看：原来的毛病改掉没有，成立的句子、语气和细节有没有改丢。交稿附几行改稿说明，新增和拿掉的事实单独列出。整章则走五道工序：扫描、信息瘦身、台词隔离、动作节奏、朗读（朗读请你自己做）。

脚本找出的位置只是要回去读的地方；没找出来，也不说明没有问题。

在哪里：`assets/revision-card.md`（改稿卡，全文见[聊天用的两张卡](chat-cards.md#改稿卡)）；`references/prose-audit.md`；`references/revision-passes.md`；`references/editing.md`“要求修改时”“修订前后对照”。

```text
这段去 AI 味，在已有事实里改：套话句可以整句重写，
用原稿已有的人和物写，不加新情节；
成立的句子和连贯的动作长句不动。正文后面附几行改稿说明。
```

### 对白：人物说话不像人，或者分不清谁在说

把台词按人物分开读：是不是这个人会用的词，此刻对谁说、急不急，叙述里的书面词有没有混进他嘴里。先在句子里面改，这句话办的事、给的信息不增不减；只在新人物开口、险事刚过、三人以上同场、家常场面这几处，再按一来一回读。改稿时还会问两句：这句话带着他此刻的态度吗？是不是只有 AI 才会这样说？两句都是问法，不计数。读者认不出谁在说的地方，补一句“某某说”“某某问”，不为标明说话人编动作；原稿定不了是谁说的，它不猜，列给你。

在哪里：`references/dialogue-craft.md`；`references/revision-passes.md`“第三遍：台词隔离”。有 Python 时，`scripts/dialogue_lines.py` 能把台词按说话人分栏列出来；想按每个人物的口吻配置再扫一遍，另有默认不开的[对白声纹与反模式检查](modules.md#对白声纹与反模式检查)，命中只是回读线索。

```text
这一章的台词按人物分开读一遍：甲话少、爱反问，乙说话直、不客气。
换词不改意思，不加情节；先列问题，再给修改稿。
```

### 长篇：写到后面，前后对不上

核对时间、位置、谁拿着什么、伤势、能力、谁知道什么和伏笔。伤势、窄路、谁手里拿着东西这类状态一直起作用，直到正文写它变了。改了前面一章，先列出后文要回读的位置，不直接改后文；没读过的章节标“受限”，不说已经查过。几份设定、条例互相打架时，列出来等你定。

在哪里：`references/continuity.md`；倒叙和多线另见 `references/nonlinear-timeline.md`、`references/parallel-timelines.md`。有 Python 时，`scripts/fact_guard.py` 比对已经登记的事实主张，正文里漏登的矛盾它发现不了。

```text
第八章改了一件物品的去向。
请找出第九到十二章依赖它的位置，先列问题，不改后文。
```

### 一场戏写得平，读着不揪心

每章问五件事：谁得到或失去了什么，主角在哪一句两难，对手有没有脸（是不是一个有名有姓、有自己打算的人：有名字，知道他要什么、为什么是现在，有一句他自己说的话；背影、制服、一个组织的名字不算），压力最高的是哪一句，留下了哪个没答的问题。再分场看进场和出场时处境变没变。补压力先在已有的事件里补，不靠加能力、加打斗；平淡也可能是缺兑现，收益写足了一样有分量。写整章前，它会在内部先填一张分场节拍卡，默认不交给你，也不附在正文后；开了每章七阶段确认的，第 3 阶段“写前准备”会把它交给你看。

在哪里：`references/stakes.md`“每章五问”；`references/scene-dramaturgy.md`；`assets/scene-beat-card.md`。

```text
这一章读着平。先按每章五问看一遍，
把进场和出场处境没变的场列出来，说该压成过场还是重写；
不加打斗，不加新能力。
```

### 旧稿搁了很久，或者换了对话从头说起

保留原稿，从正文反推人物、时间线、已经发生的事、没采纳的方案和停笔的位置；对不上的并列给你，不自行补造。换对话前，让它整理当前版本、最新正文、已确认的状态、没定的问题和下一步，摘要和原文一起带到新对话里。工坊没有长期记忆，作品和满意的版本请自己保存。

在哪里：`references/manuscript-import.md`；`references/projects.md`“换AI或会话”；`assets/story-state-template.md`。

```text
保留原稿，整理人物、时间线、已发生的事实、没采纳的方案和当前停点；
有冲突的并列给我，先不续写。
```

此外还有世界观与大纲、人物关系、能力与升级体系、只审不改的审稿、扫榜与拆文、封面方案、Word 和 PDF 交付等，见下文[功能全览](#功能全览)。

## 任务分级

改一句话、精修一整章、回查多章，所需的阅读和核查不同。工坊按任务类型分三级，不按篇幅。

| 级别 | 适用情况 | 怎样处理、交付时你会看到什么 |
| --- | --- | --- |
| L0 轻量 | 改几句、润一段、讨论设定、局部点评 | 读相关的一个主模块，检查一次后直接给结果，不附流程 |
| L1 整章 | 写一整章，或整章精修、重写、去模板腔、审稿 | 读整章必经的方法，检查表达、场面、连续性与修订变化；四项交付状态记在工作记录里，你要报告时附上（只要正文时不插进正文） |
| L2 多章或定本修订 | 两章以上、批量重修、改已采纳的章节、续写依赖多章事实 | 包含 L1 的要求；先做一章试点，每章各有状态，改了前章就列出要回查的后文 |

可以直接说“按 L1 精修整章”，也可以授权“一次处理第 2—4 章，不用试点”；这样处理出来的每章仍是候选稿。说“继续”或“我累了，你决定”，表示在当前目标内接着做：普通的场景组织和措辞由 AI 自己选，会改变剧情的缺口它会先指出来。

## 写作与改稿流程

### 写新章前

落笔以前，先回到故事真正停住的地方：人物在哪里，手里有什么，知道多少，下一步又想得到什么。再准备三样材料：

1. **场景变化与节拍**：人物想得到什么，遇到什么阻力，结束时处境怎样变化。落笔前 AI 在内部填分场节拍卡；r5.54 起节拍卡多了三栏：这一场谁在乎什么、场上的人声、接上一场。
2. **作者声音样本**（包里规则和两张卡说的“作者”就是你）：从你已采纳的原文里摘，保持叙述距离和人物口吻。没有你写过的文字时，AI 会照实说这次没有声音样本。
3. **现场素材**：空间、道具、动作条件，以及图片里真正要借的部分。

### 写完以后：修改的五道工序

整章写作和整章修改写完以后，默认都走这五遍。每一遍只看一件事：前两遍决定哪些句子留（先删），后三遍打磨留下的（后改）。

| 工序 | 核查重点 |
| --- | --- |
| 扫描 | 重复词、段尾的“没有……”、长短相近的动作短句连排、“一个……一个……一个……”的排比等回读线索；命中只是要回去读的位置，不等于判错 |
| 信息瘦身 | 盖住段尾句、复盘句、讲设定的台词，问读者少了什么：事实、口气、认识的变化、停顿或余韵；都说不出来才删 |
| 台词隔离 | 分两步（r5.54）：句内每句都过，只在句子里面改：换词，补回漏掉的动词和“真、还、又、才”这类小字，加减语气词，调语序和停顿，这句话办的事、给的信息不增不减；来回（谁出声、添或删一个分句）有条件，只挑几处。按人物分栏读台词，问用词像不像他、对谁说、急不急、叙述的词混进来没有、这句话带着他此刻的态度吗、只有 AI 才会这样说吗 |
| 动作节奏 | 过渡动作压缩，关键动作展开；同一个人顺着同一股冲势连着做完的几下可以一口气写完，不硬拆成碎句；走位与障碍是否成立 |
| 朗读 | 你出声读或用 TTS 听，找拗口和换气不顺的地方；AI 听不到声音，没做朗读就照实说 |

修改之后，把前后段连起来读，确认没有带进新的重复、事实或语义损失，也没有误删重要细节。整章编辑还会从段落密度与语义分段、对白与标点、场景可还原性、叙事功能、跨章连续性、修订前后对照六个维度各写一条结论：达到、有问题、未看或不适用。有没看的维度，就不能说“精修完成”。

### 可选：每章七个阶段逐步确认（章节门）

你明确开启以后，写新的一章分七个阶段交成果，每个阶段等你确认再走下一个，不跳、不并。把一章重写出新的一版、接着写一章只写了一半的稿子算不算，它先问你一句，不默认走：

1. 材料与目标
2. 章节方案
3. 写前准备
4. 初稿
5. 审稿与修订计划
6. 修订稿
7. 定稿记录

- “继续”这类话只放行正在等的那一个阶段；“你决定”只授权这一阶段里可撤回的选择，不算确认。最后一步要你对当前这一版明确说采纳，比如“定稿。”“采纳当前稿。”；“就这版吧”这类话它会多问一句。批量写章也是每章各自确认，一章通过不解锁下一章。
- 只做分析、逐字保真排版、局部标点修复这类限定任务，保持原来的范围，不扩大成七步。
- 你改了方案或正文，重开受影响的那一步，它后面的旧确认作废，历史留着。
- 开了以后还有两项策略，你和作品档案都没另说的，都按开着办：写前必须有实际的看图准备（你给参考图，或者让它去找）；初稿由你自己交给你选的教师（人或另一个 AI），再把意见或改稿带回来，工坊不自己扮教师。不要的说一声：整本书都不要的，记一次你的原话；只这一章不要的，当章说，只管这一章。整本书的做法改了，只对之后才开始的章节生效。
- 合并候选版起有脚本记这些：`chapter_gate.py` 读进度，`learning_loop.py apply` 记每一步的展示、你的确认、重开和教师回传，绑定展示实例、版本和稿件哈希。回传绑的不是当前这一版初稿的，拒收；初稿换了版，旧回传留作历史，不套到新稿上。r5.55 起，这一章实际按什么策略走，看 `status` 里的 `workflow_policy`。

怎么开、命令怎么写、实际跑出来是什么样，见[四个可选模块](modules.md#章节门)。脚本只核记录之间对不对得上，认证不了原话真假，也不判断稿子好坏。

只能聊天时没有脚本，由 AI 人工记版本、阶段和你的原话。交付门卡里没有这一页的内容，要另贴这一页规则（约 13,900 字符），和交付门卡一起贴进项目指令或第一条消息；教师的结果回来时，再贴“教师回传怎么审”那一页（`references/teacher-review.md`，约 5,400 字符）。章节确认这一页有两种拿法：

- 更好走的：从完整包里直接拿 `skills/novel-workshop/references/chapter-confirmation.md` 整个文件，用文本编辑器打开，全选复制。
- 只有单文件时：在单文件里搜“内嵌内容：references/chapter-confirmation.md”，从标题下一行起，复制到下一行 `-----` 为止。单文件很大，手机上不好选，最好在电脑上做。

### 别人改过的稿子怎么审

你把教师、编辑的意见或改稿带回来，或者问“他改得对不对”时，工坊照包里的“教师回传怎么审”一页做（r5.54 加的读法）：

- 先逐句还原他改了什么，每一处写一句“他想解决什么”。这是推断，标成推断。
- 读者在不在现场、感情到不到、对白像不像这个人，只有你读了能定，工坊不逐处答是或否；你对这本书要什么效果没有记录的，它问你。你当前的要求、锁定的原句、既定事实和人物口气排在教师意见前面；它不替教师辩护，也不为了显得有主见驳他。
- 每一处写拟处置（采纳、拒绝、暂缓）和依据，再写由谁来定：硬错由工坊核对，措辞口气由你定，查不到依据的事实列为待核，结构、情节、人物做了什么和知道什么、台词的增删只有你能定。
- 认问题，不照抄改法。并排给你看的每一处只写两样：改了以后多了什么、丢了什么。最后给你一张短表：位置、原句、教师的改句、工坊的改法（如有）、多了什么、丢了什么、拟处置和依据。
- 你可以整份确认，只点出例外；确认以后才按获准的范围改。只说“直接改”“按老师的改”的，它先交方案并问一句。工坊拟“暂缓”的，等你说了再动。教师的稿子不直接覆盖初稿，也不等于你采纳。
- 改完对新稿实际复查，不拿上一版的结论顶。最后采不采纳，仍等你看过当前这一版修订稿再明确说。

怎么记（合并候选版起）：开了章节门的教师交接，回传用一条 `teacher_return` 事件登记，绑定当前这一版初稿；项目开了[学习循环](modules.md#学习循环)，每条意见怎么取舍、实际改了什么、新稿查没查，都记进同一份项目记录。只能聊天时，人工记在同一份工作记录里。

照实说：这套读法和记录流程只用合成稿走过，还没有在一份真的回传稿上验证。“多了什么、丢了什么”是工坊的读法，不是结论；对白读感由你定。

## 交付状态

一份稿子交到你手里时，读了什么、查了什么、还有什么待定，都应当有记录、问得出来。整章以上的任务把这些分成四项记录，你要看时，它这样附上：

```text
【交付状态】第5章｜候选稿 sha256:1a2b3c…
INPUT_READY：READY
MECHANICAL：GREEN
EDITORIAL：PASS［自查］……
AUTHOR：NOT_ACCEPTED
```

| 项目 | 意思 | 你需要做什么 |
| --- | --- | --- |
| INPUT_READY | 原稿、前文、规则文件都在，版本对得上；不代表已经读过 | BLOCKED 时补材料 |
| MECHANICAL | 声明过的程序检查是否真在这份稿子上跑过、结果如何 | GREEN 只说明声明过的检查通过；UNTESTED 是没跑；STALE 是检查后稿子、依据或工具变过，要重跑 |
| EDITORIAL | 内容审读的结论，写明是自查、独立代理还是人工编辑（审稿方式是自报的，脚本无法核实） | 自查不等于独立审稿；NEEDS_REVISION 表示要返修 |
| AUTHOR | 你有没有明确采纳这一版 | 满意就说“采纳这一版”；在那之前都是候选稿 |

四项不能互相替代：机器检查是 GREEN，不代表文笔好；编辑写了 PASS，不代表你同意。只有你明确采纳的版本，才会写回设定、状态档案和后续章节的事实基线。你也可以说“不用审了，直接采纳”，记录会照实写“作者决定跳过审稿”，不会补写一份审稿。

四项状态和这次读过的模块，一般记在工作记录里，不整份附在正文后；要看就说“附上交付状态”“列出这次读过的模块”。这不是绝对的：包里规则也要求，机器检查和审读没有都通过的稿子交给你时，照实附上状态；聊天里脚本一般不跑，没跑时 MECHANICAL 就是 UNTESTED，所以也可能附上。

默认随稿交给你的有这几样：

- **改稿说明**：改稿任务在正文后附，说明本身一般不超过十行；待你定的变化另列一块，一处一行，不算在十行里。
- **起草时新加的设定**。
- **用没用风格卡的一句交代**：写新场景时，在正文外说一句这一场加载了哪张卡、为什么，或者没有对得上的卡、照原来的写法写。
- **没做的检查照实说**：比如聊天里没跑脚本、是人工对照，没读前后文，没有你的声音样本。

你说“只要正文”，就只交正文，这些另记在工作记录里，你问起再说。开了每章七阶段确认的，各阶段的成果另外交。聊天里这些记录不一定存得下，工坊也不会把没存下的说成已经存档；想留就让它贴出来，自己保存。

## 功能全览

写一本书，会遇到不同的问题：故事还没有形状，人物的选择站不住，一场戏缺少变化，或前后两章接不上。核心的 48 篇方法参考沿这些实际需要展开，下面归为 22 组，方便找到眼前要用的部分。

| 功能 | 能做什么 | 提供什么最有帮助 |
| --- | --- | --- |
| 构思、世界观、大纲 | 将点子变成人物目标、阻力、具体事件和因果链；规划分卷、章纲、书名与简介 | 题材、核心画面、主角想要什么 |
| 人物与人物关系 | 检查欲望、动机、退路、合作与反目；设计出场、成长和复杂交涉 | 已发生行为、关系现状、不能改的设定 |
| 能力与升级体系 | 设计使用条件、代价、限制、资源门槛和升级带来的新选择 | 能力现状、已有战斗与明确边界 |

## 风格包

完整包附带两个风格包，在 `skills/novel-workshop/assets/style-packs/`。它们是两套单独的写法规范，各有自己的入口文件 `ENGINE.md`（r5.54 叫 `SKILL.md`，合并候选版改了名）、规则数据、现成提示词和检查脚本。r5.55 起，包自己的 README 写明：要单独当技能装，先把 `ENGINE.md` 改名为 `SKILL.md`；这样装平台认不认，没有验证，这里按“跟着工坊用”来说。

| 包 | 版本 | 管什么 |
| --- | --- | --- |
| 都市高武风格引擎库（`urban-martial-style-engines`） | v2.0.2 | 都市高武这一题材：主角模板、三槽引擎（人物底色、战斗物理、副本规则）、卷配方、节奏、品阶火器机构的口径、术语 |
| 小说实感与去 AI 味引擎（`universal-novel-realism-engine`） | v17.1.2 | 不分题材的句法、排版、套话：内核加六个弹药包、80 条禁令、节奏硬指标 |

- **默认不用**：你在请求里点名，或者在作品档案的“启用的风格包”写上，才会按它写或查。题材看着对得上也不会自己启用，也不拿包里的禁词、句长、段长去查你的稿子。
- **点名**：“这一章按都市高武引擎写，配方用寒门开局”“用去 AI 味引擎的内核加搏杀包过一遍这段”。
- **长期启用**：在作品档案里写哪个包、用哪几样，以及你采纳成本书规则的硬指标（禁词、句长、段长）。没采纳的硬指标只当复核线索：报了就去读那一处，读下来确实有毛病才改，不为了让脚本不报去改你的句子。
- **排在哪里**：包里的规则排在你这次的话、你的原文、已采纳的事实和本书规则之后。同时启用时，句长、段长和断句照工坊的做法（看读者跟不跟得上，不看长短），包里的字数定额只当参考；和工坊说法不一样、你又没说过的，先问你。
- **包里的脚本**：查禁词和 AI 腔、查引擎能不能同用、导出提示词、重建 `library.json`，在你自己的电脑上运行，命令见各包的 README（读设定档要先 `pip install pyyaml`）。工坊不会自动运行它们；制作环境也没有运行过。
- **只有聊天**：单文件不带风格包。要用哪个配方，就把包里 `prompts/` 下对应的那一份提示词整份贴进对话，再上传单文件。两个包同用，实感引擎那边改贴 `07_与都市高武同用.md`；要换引擎，改贴 `00_底座与目录.md` 和选中引擎的 yaml，最多三个。
- **来源与许可**：两个包里没有单独的许可文件，以完整包根目录的 `LICENSE`（MIT）为准，和仓库根目录的 `LICENSE` 是同一份。

## 能力边界

- 普通写作不需要自行配置模型 API 或 Python；运行脚本才需要对应环境（Python 3.9 或更新，工作台要 Node.js 18 或更新）。
- 工坊是一组文件：模型读没读、照没照做，取决于平台和模型本身。本包不能保证任何平台会自动运行本地脚本；没有运行时，程序检查应当写成 UNTESTED，而不是 GREEN。
- 不能判断一段文字是不是 AI 写的，也不能用句号比例给文笔打分。
- 运行 Python 不等于完成了文学审稿；同一个模型复查自己，不等于独立编辑。
- 事实比对只核对已登记、已声明的主张，正文里漏登的矛盾，程序发现不了；没读过的章节不能声称已检查。
- 交付门脚本拦得住疏忽，拦不住有意伪造：审稿方式、读过的来源、保留理由都由审稿记录自报，状态文件也可以被手工改写。状态块说明的是“记录了什么”，不是“已被证实”。
- 一次测试的结果，不能推广到所有题材、所有模型；r5.54 那次新旧规则的对照只用了同一个模型系列，r5.55 没有做文笔对照。聊天产品这条路只做过模拟检索的测试，没有在真实的聊天产品里量过附件能读到多少。
- 压缩包校验通过，只说明文件完整，不说明小说质量。
- 市场观察要带上真实榜单、截图、表格，或使用可联网的环境；封面实际成图需要生图工具；交付 Word、PDF 等文件需要对应的导出与验收工具。工坊提供这些任务的方法，实际能做到什么取决于当前环境。
- 章节索引不代替文学分析；关系图需要已有的关系表；工作台按文件名搜索，不是全文检索。
- Darwin 只在你要求维护时使用，TypeSafe 属于可选开发扩展；安装不等于启动后台自优化、联网服务或定时写作。
- 四个可选模块只记录和核对：认证不了谁说过什么、评审是不是独立，存下示范不是微调，也不证明文笔变好。教师回传流程只用合成稿测过；真的回传稿、在你电脑上的安装、对白自然度，都还没有验证。
- 各脚本在不同系统上的限制见[本地工作台与检查工具](tools.md#运行条件与平台限制)：`project_state.py`、`learning_loop.py` 和 `chapter_gate.py status` 读写都靠同一种 POSIX 文件锁，原生 Windows 不支持；`chapter_gate.py status` 和 `dialogue_lint/run_lint.py` 要用普通的 `python3 scripts/…` 运行，不能加 `-I`。
