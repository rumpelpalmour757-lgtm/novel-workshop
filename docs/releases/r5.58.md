## 改了什么

- **宪法 NWC-1.8**（`CONSTITUTION.md` 第一节，两处都只在原条文末尾加句，原句不动）：第 3 层“作者当前的明确决定”写明，这里的作者指对这部作品有最终决定权的人；合著的书，作品档案写明谁拍板，没写明的先问清楚，问清以前几位作者说法不一样的，哪一种都先不执行；教师、编辑、读者和没有最终决定权的合著者的话（你转来的也一样），记下是谁说的、在哪里说的，当资料对待，不记成你的原话，也改变不了这本书的项目规则和已采纳的故事事实；你说了照其中哪几处办，这句话才是决定，它定的只是听不听、听哪几处，怎样落实仍照你定下的流程走（开着新章全流程的，先交取舍方案）。《AI 协作宪法》第 3 层里授权别人代为决定的那一句没有带过来：带过来，别人的话就可能顶掉新章各阶段的确认和定稿采纳。第 1 层“平台和法律的要求”写明，这里的平台指运行工坊的 AI 应用或网站；作品要发表的连载站、出版方对稿件格式的要求（字数、章名、排版），你定为本书规则的才归第 5 层（本书的规则），没定的当资料，用得上时提醒你；稿件内容合不合法，照这一层的法律办。十二条原则、第一节其余几层、“同一层之内”和其余条文没变。这里的 NWC-1.8 和撤下的 r5.41—r5.43 里用过的 NWC-1.8 不是同一份条文，编号接着 NWC-1.7。作品档案模板（`assets/project-template.md`）的“维护选择”跟着加两行：“拍板的人（按需）”“发表平台的要求（按需）”；登记表 `assets/constitution-rules.json` 的版本改成 NWC-1.8，CON-001 的落点加一项测试。程序能核的只有定稿一关的一部分：带“编辑说”“老师说”的转述不记采纳；前六关的确认、学习记录里记成谁的意见、作者偏好记不记，脚本认证不了是谁说的，靠工坊照做。
- **你点名改已采纳章里的一处**（`references/editing.md`“先定范围”里新加的“作者点名的一处小改”，定义只写在这里，别的页都指这一段）：你在当前消息里点明改已采纳章里的哪一处、改成什么，说只改这一处的（一个词、一句话、一个数、一个称呼），你这句话就是修改决定：照改，不先问，也不扩成 L2 的整套；那几个字在这一章里不止一处、认不准是哪一处的，先问一句。这仍是宪法第三节的受控变更：记你的原话；改好以后连着前后句读一遍，改的是叫法、数目、东西在谁手上这类事实的，照连续性“修订后的回归核对”查后文，查到的只列给你，不自己跟着改；另一章正在走新章全流程、已经确认的阶段用到了改掉的说法的，从受影响的阶段重开；新版是候选稿，不说“已审”“定本”；有交付门状态文件的，先用 `replan` 记下你这句话再改（用合成材料实际跑过：覆盖原文件以后 AUTHOR 是 NOT_ACCEPTED，机器检查和审稿是 STALE，“改已采纳的文本”是 REVIEW_REQUIRED）。不算这一种的：几章、几处一起改的按 L2；没说改成什么的照分级办；工坊自己看出来要改的，先列给你；这一章还在新章全流程里的，从受影响的阶段重开；已经定稿的章不补走七个阶段。这是这一版唯一减轻默认流程的一条：照 r5.57 的字面，点名改一个字也要走 L2 的整套。`SKILL.md`“任务分级与必经检查”、`references/quality-loop.md`“阶段与权限”表、包内 `USAGE.md`“选择检查强度”各加一句指到编辑页那一段，L2 那一行原文不动。
- **新规则入册以后，已采纳的章怎么办**（`references/continuity.md`“先查再入册”“规则打架时”）：按新版执行，管的是以后新写的章和新写的部分；已采纳的章不因为新规则自动改，和新规则不一样的地方（`rule_register.py collide` 能列出旧叫法在哪一章哪一行）列出来请你定，你点明改哪些，再走受控变更，后文照“修订后的回归核对”回读。规则文件里写着“前文也统一改”的，同样列出来请你点明：规则文件压不过已采纳的故事事实。你让精修一章已采纳的稿子时，用词规则在这一章里报出的旧叫法也列给你，不顺手换掉。写明了期限的临时规则，过了期限就不再据它写新章（期限写在登记表这份来源的 `note` 里，`check` 不看日期）。整份条例换了新版、旧版标成被取代，不等于旧版里每一条都撤销了：新版没有改写、也没有点名删掉的具体例外照旧有效。这几种情形用 `rule_register.py check` 实际跑过，`rule_register.py` 没有改。
- **你转来别人的话怎么记**（`references/teacher-review.md`、`references/author-preferences.md`、`references/learning-loop.md`、`references/chapter-confirmation.md`）：编辑、读者、没有最终决定权的合著者的意见和改稿，也照“教师回传怎么审”那一页分类、写拟处置、写谁来定；他们的话记在他们名下，写明是你转来的，不记成你的原话；你说了照哪几处办的，记你那句话。转来的话不算你的偏好：你说了“以后照这个来”的，记你这句话；只是转来、没说用不用的，不记。学习循环里不把转来的意见记成评审（记成 `author`，工坊就不能拒绝这条意见；记成 `teacher`，他们说“可以”时这一轮会记成教师审过；这两样都用合成记录实际跑过）；你说了照其中哪几处办的，把你这句话记成 `role` 为 `author` 的评审。你转述别人的话（“编辑说大纲可以”“老师说能定稿了”）不是你的确认，工坊先问一句；第 4 阶段你带回对得上初稿的教师结果，照原来的做法记初稿的确认，教师结果里写的“能定稿了”不算对定稿的确认。章节门最后一关的脚本不记带“编辑说”“老师说”的转述（6 种说法实际跑过，都没有记）；它认不出话是谁说的，原样贴来的“定稿。”照样会记，要靠工坊照实问清。`chapter_gate.py`、`learning_loop.py` 没有改。
- **工坊发现以前交的有错，主动说**（`references/quality-loop.md`“交付状态”新加的“工坊发现自己以前交的有错”，`references/chapter-confirmation.md`“交出以后发现有错”）：交出去的正文、设定整理、事实账条目，或者交付说明里说过的检查结果，后来发现有错，主动告诉你，不等你问，也不因为这一次的任务管不到那里就不说。只管错（事实、连续性、说过的检查结果、硬性的标点错），可改可不改的写法不算。写明错在哪一版哪一处、怎么发现的、对的应该是什么、依据在哪；已采纳的章、你确认过的设定和事实账条目都只标不改，你定了再照宪法第三节改；说过的检查结果站不住的，把那句话收回，照实写现在的状态。这一次的任务照常做，不顺手改范围以外的那一处；你只要正文的，记进工作记录，你问起时、或者下一次能附交付说明时再说。章节门里还没定稿的阶段，不在交出的那份上暗改，只用现有的重新展示、重开和第 5 阶段方案，不跳、不并任何阶段。这一条维护者照建议选了不改宪法，只改模块。没有程序能发现工坊自己以前的错，测试只核条文在不在。
- **照你的条例、手册审稿，写得模糊的规定**（`references/quality-loop.md` 区分四类发现那里、`references/continuity.md` 各一句）：照你的条例、手册、文风卡审稿时，有条目没照做，不单凭这一条记成明确违背要求；条目自己写了程度或例外的（比如“一般不超过三行”），照它的目的读；拿不准是不是你有意的要求，列给你，不径直记成可选；审稿记录里写明是哪一条没照做、记成了哪一类。规定写得模糊的（比如“打斗要利落”），按它的目的理解，把怎么理解的写进交付说明或工作记录，不自己改成可以计数的指标；写明了数字的不算模糊。“同一层之内要不要先分强弱”这一条，维护者照建议选了不改宪法：五步的结果不变，冲突登记表不加强弱一项。

## 没有验证的

真实写作里会不会照这些页办（成对场景测试只有 21 个合成场景、每种环境两次，评分要点照这一版的条文写、又在看过第一轮结果以后改过；点名小改做得太重或太轻，只在这几个场景上看过）；点名小改在返修额度用完时的做法，这一轮没有新跑；“听谁的”：脚本认证不了是谁说的，前六关、学习记录里的评审角色、作者偏好记不记都没有程序检查，学习记录里不记编辑、读者的意见以后会不会少了有用的东西，也没有验证；“发现以前的错”、照条目审稿、模糊规定按目的读这几句，没有任何程序检查，只是条文；“所在平台”是对照时看出来的字面问题，没有出过事的记录；匿名对照材料检查没在原生 Windows、macOS 上跑，技能目录在产出里换了一种写法的（比如经过另一个符号链接）默认查不出来，要用 `--identity-marker` 登记，没用真实模型做过评审，脚本拦下不等于材料已经盲了；原生 Windows、macOS 上的全套测试；文笔有没有变好。从这一版退回 r5.56 或更早，没有实际走过。r5.57 的说明里列的几项（Word、PDF 的文字提取，真实的教师回传，真的 gemini-4-argon 调用，不分大小写的文件系统，在你电脑上的安装，平台自己管的技能目录），这一版的验证记录里也没有。

## 升级要注意的

- 已经装过旧版的，用 `python install.py --upgrade`（装的时候带了 `--dest` 的也带同一个；先加 `--dry-run` 看输出，技能后面写 `upgrade` 或 `unchanged` 才对）。不加 `--upgrade` 时，装着的版本和这一版不同，安装器就停下，什么也不装。
- **从 r5.57 升上来**：先 `python install.py --upgrade --dry-run` 看一遍，再 `python install.py --upgrade`。装着的 `assets/project-packs/`（`_author/` 和你放进去的作品资料）照旧列在 `carried` 里带进新版，逐个核哈希；完整包不带那里的任何文件，所以不会有 `conflicts`。交付记录照旧：五个绑定脚本没有变。宪法变了：r5.57 时开始的交付门任务，`status` 的 `governance_warnings` 里会有一条“宪法或规则登记在任务开始后变了”，只是提示，四项状态和权限裁决不变，旧结果不作废（用合成任务实际跑过）；照 NWC-1.8 复核受影响的判断，比如有没有把转来的话记成你的。写作这边没有不兼容的变化。
- 合著的书，在作品档案“维护选择”里补上“拍板的人”；连载站、出版方的格式要求要当本书规则的，补上“发表平台的要求”。没写的，几位作者说法不一样时工坊先问，发表平台的要求只当资料。
- 用维护扩展拿 r5.57 和这一版做对照评测的：这一版改了宪法和登记表，`freeze` 时要附上宪法改动的批准记录（`--constitution-approval`），否则评测工具不给“候选更好”的结论。`darwin_eval.py` 有几处不兼容的变化：`blind` 查到版本线索，或者一边的产出是空的、不是 UTF-8 的，以退出码 2 停下，不再照样打包；结果 JSON 多了 `format_differences`，封存的映射文件多了 `identity_markers`、`format_differences`。用 r5.57 建的评估目录，换成这一版的 `darwin_eval.py` 照样能 `verify`、`verdict`、`unblind`、`summarize`（用合成材料实际跑过）。
- **从 r5.56 或更早升上来**：命令一样，照 [r5.57 的说明](https://github.com/rumpelpalmour757-lgtm/novel-workshop/releases/tag/r5.57)的“升级要注意的”办；中间各版的不兼容变化照样适用。从 r5.56、r5.55、r5.54-merged 升上来的，交付记录照旧；从 r5.54、r5.53 的包（文件名不带 merged）升上来的，以前记的整章交付记录读成过期（STALE），要用这一版重跑一次检查。
- **退回 r5.57**：用 r5.57 的包运行 `python install.py --upgrade`（装的时候带了 `--dest` 的照样带），装着的 `assets/project-packs/` 照样带进 r5.57，较新的一版整份留在备份里，这一步在临时目录里实际走过。退回以后宪法回到 NWC-1.7，这一版开始的交付门任务也会提示宪法变了（照脚本的写法推的，没有另跑）；交付记录两边照旧，是按五个绑定脚本的哈希推的。
- **退回 r5.56 或更早**：r5.56 的安装器同样带 `assets/project-packs/`；r5.55 和更早的安装器不带，记录留在这次退回新生成的备份里：`<安装位置>/.novel-workshop-backups/<时间>/novel-workshop/assets/project-packs/`，取最新的那个时间文件夹。怎样取回，照 [r5.56 的说明](https://github.com/rumpelpalmour757-lgtm/novel-workshop/releases/tag/r5.56)和[回到旧版](https://github.com/rumpelpalmour757-lgtm/novel-workshop/blob/main/docs/versions.md#回到旧版)。这一版的安装器和 r5.57、r5.56 逐字节相同，做法一样；从这一版退回 r5.56 或更早，没有实际走过。
- 手动回退（把备份里的目录移回原处）的：备份里的 `assets/project-packs/` 是升级那一刻的；移走现装的目录以前，先把它的 `assets/project-packs/` 另存一份。
- 以后从更新的版本退回 r5.58：用 r5.58 的包运行 `python install.py --upgrade`，记录照样带进 r5.58，较新的一版整份留在备份里。
