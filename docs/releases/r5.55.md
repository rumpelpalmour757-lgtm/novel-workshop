# 小说写作工坊 r5.55 修订候选版

版本号 `2026-11-14-r5.55-candidate`。在上一版合并候选版（版本号 `2026-11-14-r5.54-merged-candidate`，文件 `novel-workshop-commercial-r5.54-merged.zip`）上做的修订候选，维护者还没有采纳：章节门和教师回传的规则改回 r5.54 的说法，修了上一版列出的四处已知问题，许可文件放进了包里。

## 下载哪一个

- **`portable-novel-workshop.md`**：便携单文件，给只能聊天、能传附件的 AI 用。没有可运行的脚本，也不带两个风格包。1,244,407 字节（约 56 万字符），SHA-256 `3eb55e24a31f93f2165e8a4c718e3312c36407e8ad92355bf86a892e0eceb958`。
- `LICENSE`、`THIRD-PARTY-NOTICES.md`：许可全文和第三方组件说明，和仓库根目录的同名文件相同。完整包里也带着 `LICENSE` 和一份按包内路径写的 `THIRD-PARTY-NOTICES.md`。

装法、用法和第一条请求见[仓库首页](https://github.com/rumpelpalmour757-lgtm/novel-workshop)和[详细用法](https://github.com/rumpelpalmour757-lgtm/novel-workshop/blob/main/docs/usage.md)。

## 改了什么

- **新章全流程（章节门）**：只管写新的一章；把一章重写出新的一版、接着写半章算不算，先问你。开了以后，你和作品档案都没另说的，写前看图和初稿由你交教师两项默认开着（合并候选版默认关着），工坊不自己扮教师：写前准备要有实际看过的图，初稿你确认以后，要等你把教师的意见或改稿带回来才往下走。没有图、没有教师，就说一声关掉；只这一章不要的，说一声，工坊记下你的原话、只管这一章（脚本里叫 `chapter_policy`）。
- **最后一关只收明确的采纳**：你的原话整句要是对当前稿的采纳，比如“定稿。”“采纳当前稿。”；“继续”、推迟、带条件、问句、否定、指别的版本的说法，以及脚本认不出的说法，都留在等待，工坊再问你一句。
- **教师回传**：放回 r5.54 的几句：读感只有你读了能定；你对这本书要什么效果没有记录的，问你；拟“暂缓”的等你说了再动；不替教师辩护。
- **学习循环、示范记忆**：你的否定意见工坊不能驳回，只有你自己说撤回才撤回；你的采纳要你明确的原话，“继续”不算。示范记忆列索引时把符合条件的案例全部列出，一次取用仍最多三条。
- **对白声纹检查**（dialogue-lint 1.2.0）：角色一栏只给数字，不按人物下结论；认“”「」『』三种引号；原来默认查的几个词组拿掉了，要查的在本书配置里列；在 Python 3.9 上也能用（包内这一组测试在 3.9.25 上都过；合并候选版在 3.9 上一导入就报错）。
- **作者改法累计**：挪出技能目录，放在你自己的作者档案那里，升级安装不动它。
- **风格包**：两个包的说明改了单独安装的几句：入口叫 `ENGINE.md`，要单独当技能装，先改名为 `SKILL.md`（没有试过）；仍然默认不启用。
- **新加一页“从改稿记录里学编辑判断”**：默认不开，你明确要求才开，只管这本书；按处记改稿案例、提炼判断卡，初稿交教师以前照卡自审。只有说明页和模板，没有脚本，没有在真的章节上试过。这一页不在维护者 2026-11-14 同意的那几件事里，是另照一份设计稿加的；留不留在这一版，还要维护者定。

## 上一版列的已知问题

[`r5.54-merged`](https://github.com/rumpelpalmour757-lgtm/novel-workshop/releases/tag/r5.54-merged) 的说明里列了四处，这一版都修了，包内有对应的测试；[四个可选模块](https://github.com/rumpelpalmour757-lgtm/novel-workshop/blob/main/docs/modules.md)一页又拿合成材料把这四处各试了一次：

- 学习循环里，你对当前稿的否定意见可能被一句理由驳回：修了。你的否定意见每一条都只能记成照改，工坊不能驳回；只有你亲口说撤回才撤回。
- “继续”一类的话可能被记成采纳：修了，“继续”记不成采纳。
- 定稿一关会把“还没到定稿的时候”这类话记成最终采纳：修了，这类话留在等待。
- 对白检查只认“”引号：修了，也认「」『』。

## 验证到哪一步

- 包内回归测试 1,589 项，在 Linux 上跑：Python 3.13 上跳过 5 项，其余全部通过；Python 3.9.25 上跳过 74 项（多跳的是没装 Pillow、PyYAML 的几项和 Crawl4AI 要 Python 3.10 以上的几项），其余全部通过。测试只说明规则写进去了、脚本照说明工作，不评价文学质量。
- 改动、复核和测试都是同一个模型（Claude）的新实例做的，不是独立评审；这一版没有做文笔对照，不说明写得更好。

## 没有验证的

文笔有没有变好；真实的教师回传；在你电脑上的安装；原生 Windows；章节门读早先版本记下的真实旧章节记录（缺不缺身份字段，没有拿实物核对）；退回合并候选版以后，它的脚本能不能读这一版写下的记录；风格包改名以后单独当技能装；编辑判断在真的章节上用；对白检查在真稿上的报告。

## 升级要注意的

- 已经装过旧版的，用 `python install.py --upgrade`（装的时候带了 `--dest` 的也带同一个；先加 `--dry-run` 看输出，技能后面写 `upgrade` 或 `unchanged` 才对）。不加 `--upgrade` 时，装着的版本和这一版不同，安装器就停下，什么也不装。
- 从合并候选版升上来：交付记录照旧（交付记录绑定的五个脚本没变；这是按脚本哈希推的，没有在这一版上另跑）。章节门新开的章，看图和交教师两项默认开着；合并候选版下已经开始、当时没说要不要看图和交教师的章，照两项都关走，工坊会问你一句。
- 章节门读旧记录更严：已确认的阶段在记录里缺你的原话或出处的，读成未确认；后面已经压着别的阶段的，要从那一阶段带你的原话重开。
- 对白检查默认不再查原来写死的几个词组，要查的词组得在本书配置里列出来。
- 从 r5.54、r5.53 的候选包（文件名不带 merged，比如 `novel-workshop-commercial-r5.54.zip`）升上来：以前记的整章交付记录会读成过期（STALE），要用这一版重跑一次检查。
- 用合并候选版时让工坊记过“作者改法累计”（你认可过的改法）的：这份记录现在放在技能目录以外、你自己的作者档案里，升级不动它。原来记在技能目录 `assets/project-packs/_author/` 下的，升级以前先移出来；已经升级过的，到装技能的目录下（默认 `~/.codex/skills`，Claude Code 是 `~/.claude/skills`）的 `.novel-workshop-backups/<时间>/novel-workshop/assets/project-packs/_author/` 里取回。
- 想退回合并候选版：用它的包运行 `python install.py --upgrade`。这一版写下的章节记录和学习记录，合并候选版的脚本能不能读，没有验证，退回以前先另存一份。
